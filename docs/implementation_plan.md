# AI 분석 엔진 안정화 및 정확도 개선 계획

AI 분석이 간헐적으로 실패하거나 점수가 0점으로 출력되는 문제를 해결하기 위해 다음과 같이 엔진을 고도화합니다.

## 핵심 개선 방향

### 1. 데이터 구조 표준화 (영어 키 도입)
- **문제**: 한국어 키("관련 전공" 등)를 JSON 키로 사용하면 LLM이 미세하게 다른 이름을 사용하여 파싱에 실패할 확률이 높음.
- **해결**: 내부 데이터 통신에는 고정된 영어 키를 사용하고, UI 출력 시에만 한국어로 매핑하여 데이터 유실을 방지합니다.

### 2. 분석 안정성 강화 (재시도 로직)
- **문제**: 병렬 호출 시 일시적인 API 오류나 타임아웃으로 분석이 전체 실패할 수 있음.
- **해결**: 개별 분석(`runAnalysis`) 실패 시 최대 1회 재시도(Retry) 로직을 추가하여 성공률을 높입니다.

### 3. 점수 정합성 보정 로직
- **문제**: LLM이 JSON 구조를 완벽히 지키지 않거나 점수 항목을 누락하는 경우.
- **해결**: 추출된 데이터에서 유사 키를 검색하여 보정하고, `detailed_analysis` 텍스트 내에서 점수를 역추적하는 백업 로직을 구현합니다.

## 상세 변경 내역

### [Component] API Layer (`/api/evaluate/route.ts`)
- 프롬프트에 영어 JSON 키 적용.
- `runAnalysis` 함수에 재시도 로직 및 상세 로깅 추가.
- `averagedResults` 산출 시 유효한 데이터만으로 평균 계산.

### [Component] UI Layer (`EvaluationReport.tsx`, `ResumePDF.tsx`)
- 서버에서 전달받은 영어 키를 다시 한국어 레이블로 매핑하여 표시.

## 검증 계획
- 실패했던 이력서 파일로 재분석 테스트.
- 서버 로그를 통해 Gemini의 응답 품질 및 파싱 성공 여부 확인.
- 항목별 점수가 0점이 아닌 정상 범위로 출력되는지 확인.
